1. Executive Summary

DeFi Saver is the most mature DeFi position management interface on Ethereum, supporting 12 lending protocols through a unified dashboard pattern. After thorough hands-on exploration in simulation mode, this analysis identifies specific UX patterns and architectural decisions that Kamino should adopt, adapt, or avoid as it evolves its Loan Dashboard.

Key Finding DeFi Saver's biggest UX advantage is not any single feature — it's the unified action model. Borrow and Leverage live as tabs in the same creation flow. Supply, Withdraw, Borrow, Repay, Boost, and Shift are all inline on the manage page, never hidden behind separate modals or routes. This is the single most impactful pattern Kamino should adopt.

Kamino's current Loan Dashboard has strong analytics (scenario analysis, stress testing, LTV charts) that DeFi Saver completely lacks. But it falls short on actionability — the gap between "seeing the risk" and "doing something about it" is too wide. DeFi Saver closes that gap with inline actions, composable transactions, and automation triggers that live right next to the position overview.

3. Position Creation: Borrow/Leverage Unification

The single most important pattern for Kamino's Borrow + Multiply unification strategy.

DeFi Saver's "Open Position" Flow

DeFi Saver unifies Borrow and Leverage as two tabs in the same creation screen. The form structure is nearly identical — only the Leverage tab adds a multiplier slider, exchange route config, and slippage settings. The right-side preview panel dynamically updates to show resulting collateral, debt, safety ratio, liquidation price, and net APY regardless of which tab you're on.

Select collateral asset + amount → Choose: Borrow | Leverage → Configure debt / leverage → Review preview panel → Create

Kamino's Current State

Kamino separates Borrow and Multiply into entirely different products with inconsistent UX patterns. Borrow uses modals triggered from a market table. Multiply has a dedicated position detail page with an action panel on the right side. There is no post-creation upsell for automation because no automation layer exists.

Recommendation: Unify Creation Flow Merge Kamino's Borrow and Multiply into a single "Open Position" flow with Borrow/Multiply as tabs. Share the same collateral/debt selection UI. Add the Multiply tab's leverage slider and swap config as progressive disclosure. After creation, immediately offer automation setup (when available).

5. Automation UX

DeFi Saver's biggest differentiator and Kamino's biggest gap — a full automation layer for position protection and optimization.

DeFi Saver's Automation Architecture

Automation in DeFi Saver is accessible from three places: the "Automations" tab in the position detail sidebar, the dedicated "Automate" top nav tab, and the post-creation upsell modal. All six automation types share a consistent configuration pattern:

Visual ratio bar — A horizontal bar shows the current safety ratio (green), danger zone (red), and configurable trigger thresholds (draggable markers). This makes it immediately intuitive to understand "if my ratio drops below X, do Y." The bar is color-coded: red for liquidation zone, orange for trigger zone, green for safe zone.

Configuration fields — Each automation type uses the same pattern: trigger condition (ratio or price threshold), target action (repay to ratio, close position, boost leverage), and asset pair selection. The "Configure" and "History" tabs let users both set up and audit their automations from the same screen.

Six Automation Types

Automation Trigger Action Kamino Priority
Auto Leverage Management Ratio falls below / rises above threshold Auto-repay or auto-boost to target ratio P0 — Core protection

Solana Constraint DeFi Saver's automations run on Ethereum via smart contract-based Safe wallets. On Solana, Kamino would need a keeper network or off-chain automation system (similar to how Kamino's Multiply loops already work). This is a technical constraint that affects the UX — Kamino should design the automation config UI first, then figure out execution.

What Kamino Should Take

The visual ratio bar configuration pattern is excellent and maps directly to Kamino's existing risk metrics (LTV, borrow power, liquidation price). The post-creation upsell modal is high-impact and low-effort to implement. The "Automations" tab in the position sidebar provides at-a-glance automation status without leaving the dashboard.

6. Composability & Advanced Features

DeFi Saver's power-user features that create defensible differentiation.

Recipe Creator

A drag-and-drop visual transaction builder that lets users compose complex multi-step DeFi operations. Users drag action blocks (Wrap ETH, Supply to Aave, Borrow DAI, Swap on Uniswap, etc.) into a canvas to build custom transaction bundles. The Recipe Book offers pre-made templates like "Ethena x Aave Liquid Leverage" and various leveraged staking strategies, filterable by protocol and type.

Loan Shifter

Moves entire positions between lending protocols in a single flash-loan-powered transaction. Example: migrate from Aave v2 to Aave v3, or from Compound to Spark. This is powerful on Ethereum where protocol fragmentation is high.

"Combine with Another Action"

Each basic action (Supply, Borrow, etc.) offers inline links to combine it with another action in one transaction. "Supply + Borrow" or "Supply + Keep Ratio" execute atomically. This is the most practical composability feature for Kamino to adopt — it doesn't require a full Recipe Creator, just smart transaction bundling.

8. Strategic Recommendations for Kamino

Prioritized recommendations organized by impact and effort, calibrated for Solana's technical constraints and Kamino's existing strengths.

Adopt (High Impact, DeFi Saver Does This Well)

1. Inline Action Panel

Replace modal-based actions with a persistent tabbed action section on the dashboard. Tabs: Leverage / Add-Remove / Close. Show max amounts, preview new ratios inline. This is the single biggest UX improvement available.

Adopt — P0

2. Borrow + Multiply Unification

Single "Open Position" flow with Borrow/Multiply as tabs. Same collateral/debt selection, Multiply adds leverage slider. Real-time preview panel showing resulting metrics.

Adopt — P0

3. One-Click Close Position

Always-visible "Close" button that handles repay+withdraw atomically. Users shouldn't have to figure out the multi-step close sequence.

Adopt — P0

4. Combined Transactions

"Supply + Borrow" and "Repay + Withdraw" in single Solana transactions. Leverage Solana's native tx composition. Show as "Combine with..." links next to each action.

Adopt — P1

5. Post-Creation Automation Setup

After creating any position, show a modal offering to set up stop-loss, take-profit, and notifications. This is the highest-conversion moment for automation adoption.

Adopt — P1

6. Automation Visual Config

Visual ratio/price bar for configuring automation triggers. Color-coded zones (red/orange/green) map perfectly to Kamino's existing risk metrics.

Adopt — P1

Adapt (Good Concept, Needs Solana/Kamino Adjustments)

7. Stop-Loss & Take-Profit

Essential automation, but implementation on Solana differs from Ethereum's smart-wallet model. Kamino needs a keeper network or off-chain monitoring + on-chain execution pattern. Design the UX first, build infra second.

Adapt — P1

8. Collateral/Debt Switch

Powerful on Ethereum where flash-loans make atomic asset swaps easy. On Solana, this needs Jupiter integration for in-tx swaps. Technically feasible but requires careful slippage handling.

Adapt — P2

9. Notifications

DeFi Saver has protocol-integrated notifications. Kamino should implement notifications but can start simpler: email/Telegram alerts for ratio thresholds, configurable from the dashboard's risk tab.

Adapt — P1

Preserve (Kamino Advantages to Keep)

Scenario Analysis & Stress Testing

Kamino's historical event stress tests (FTX, LUNA collapse simulations) and market impact analysis are completely absent from DeFi Saver. This is a genuine competitive advantage — preserve and expand it.

Kamino Advantage

Risk Visualization Depth

LTV charts over time, interest breakdown, net value impact projections — DeFi Saver only shows a basic safety ratio percentage. Kamino's analytics tabs are significantly stronger.

Kamino Advantage

Rewards Integration

Kamino's dashboard prominently shows pending rewards and claimable amounts. DeFi Saver has a "Rewards" tab but it's minimal. Keep this front and center.

Kamino Advantage

Avoid (DeFi Saver Patterns Not Worth Copying)

Recipe Creator

The drag-and-drop transaction builder is a power-user tool with a small audience. It adds significant complexity for marginal user value. Combined transactions (Supply+Borrow) cover 80% of needs without the builder.

Avoid for now

12-Protocol Sidebar

DeFi Saver's left sidebar is cluttered with 12 protocols. Kamino is a single protocol — this navigation pattern doesn't apply. Keep the focused, single-product experience.

Not applicable

Smart Wallet Requirement

DeFi Saver requires creating a Safe smart wallet for advanced features. This adds onboarding friction. Kamino should aim for a frictionless model where all features work with a standard wallet.

Avoid — user friction

9. Suggested Roadmap

Phase 1 — Foundation (4-6 weeks)

  • Inline action panel (Leverage / Add-Remove / Close tabs)
  • Borrow + Multiply unified creation flow
  • One-click Close Position
  • Combined transactions (Supply+Borrow, Repay+Withdraw)

Phase 2 — Protection (6-8 weeks)

  • Stop-loss automation (keeper infra + UI)
  • Take-profit automation
  • Visual ratio bar config for automation triggers
  • Post-creation automation setup modal

Phase 3 — Intelligence (4-6 weeks)

  • Notification system (email/Telegram alerts)
  • Auto-leverage management (auto-repay + auto-boost)
  • Automations tab in position sidebar
  • Integration with existing scenario analysis

Phase 4 — Advanced (8+ weeks)

  • Collateral Switch (Jupiter-powered in-tx swaps)
  • Debt Switch
  • Repay with Collateral improvements
  • Boost/Repay on target price automations
Final Thought DeFi Saver proves that the "see risk → take action → automate protection" pipeline is the gold standard for DeFi position management. Kamino already has the strongest "see risk" layer in DeFi. The opportunity is to close the loop with action and automation — turning Kamino's analytics advantage into a full position management platform that makes DeFi Saver's approach look incomplete by comparison.
